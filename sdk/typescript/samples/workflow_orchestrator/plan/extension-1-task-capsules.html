Extension 1 · Task capsules

Add Kimi-style mutable decomposition without making a TODO synonymous with a worker. The root chooses whether each capsule executes inline, as one worker, or as a bounded workflow.

Execution vocabulary

Concept Owns Must not imply
TODO / capsule User-visible progress, dependencies, and acceptance evidence. A new model invocation or context.
Workflow An independently recoverable execution graph. One workflow per TODO.
Session Context continuity across related capsule work. A policy or review boundary.
Stage Authority, routing, evidence, and acceptance policy. A fresh session when continuity is still valuable.

First PR

Persist a dependency-aware capsule queue and execute one ready capsule sequentially through the existing stage kernel. Queue mutation and execution both produce trace evidence.

Continuity lease

The dispatcher may keep several dependent capsules in one session. It releases that lease only when evidence favors a boundary: independent judgment is required, capability needs change, parallel work becomes real, or the current context shows degradation.

Persist lineage as continued, checkpointed, forked, restarted, or independent_review. Final evidence can then state what a worker was allowed to remember rather than merely naming the worker.

Degradation is host-observable: repeated file reopening, repeated rejected approaches, contradictory decisions, duplicate commands, scope growth without landed evidence, or compaction near a sensitive decision. A model request to split is a claim, not sufficient proof.

Implementation path

  1. Validate unique IDs, acyclic dependencies, bounded fields, and optimistic revisions.
  2. Persist queue changes in rollout trace before exposing the new queue state.
  3. Select only a dependency-ready capsule; resolve its context and route through phases 4–5.
  4. Issue or renew a continuity lease, then map inline, worker, and workflow granularity to the existing invocation paths.
  5. Complete a capsule only from its terminal StageResult, never model prose.

Proof

A three-capsule fixture blocks unmet dependencies, rejects a cycle, resumes after restart, and produces the same ready order from trace replay. Revising one pending capsule does not rewrite completed history or reset its mission budget. Three dependent capsules can share one session; an injected degradation signal releases the lease and records the next session boundary.

Stop: sequential execution only. No swarm fan-out, recursive child workflows, automatic decomposition, one-TODO-one-workflow policy, or UI task board in this PR.
