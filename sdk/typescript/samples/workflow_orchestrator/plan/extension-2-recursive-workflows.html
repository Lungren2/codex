Extension 2 · Recursive workflow compiler

Let a running workflow delegate genuinely nested orchestration while the host preserves one authority tree, one deadline, and one finite budget.

PR contract

Proposed title workflow: execute one budget-inheriting child program
Depends on Baseline phases 1–4 plus durable restart recovery; task capsules are optional.
Decision Can depth-one delegation preserve authority, cancellation, and absolute budgets?
Rollout Child execution requires an explicit host capability and a parent budget reservation.
Rollback Disable child compilation; preserve parent and child traces as terminal evidence.

First PR

Permit one parent workflow to compile and execute one child TypeScript workflow at depth one. The child receives an explicit budget slice and a curated context projection. 

workflow.child.run({
  source, input, context, budget: {
    max_invocations, max_runtime_ms, max_stored_bytes
  }
}) → ChildWorkflowResult

Implementation path

  1. Reserve the child budget atomically from the parent's remaining bounds.
  2. Compile with the phase-3 compiler and persist source, JavaScript, map, and compiler hash.
  3. Create a child run ID linked to the parent invocation and original absolute deadline.
  4. Reject child authority, context, or routing requests broader than the parent owns.
  5. Return only a bounded result projection; retain the full child trace outside model context.

Proof

Tests prove child reservations reduce the parent budget before compilation, cancellation cascades downward, restart preserves ancestry and deadline, and attempts to exceed inherited authority fail without starting inference.

Stop: depth one, one active child, and no sibling concurrency. Do not add unbounded recursion, dynamic imports, or child-created worktrees.
