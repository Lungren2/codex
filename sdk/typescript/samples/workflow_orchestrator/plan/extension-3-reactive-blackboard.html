First PR

Add a bounded append-only board that workflows can publish to and query. The root workflow remains the sole scheduler; the board does not autonomously invoke workers. 

BoardEntry = Need | Artifact | Decision | Blocker

workflow.board.publish(entry) → { sequence, hash }
workflow.board.query({ kind, status, after_sequence, limit })
workflow.board.resolve(need_id, artifact_ids) → BoardEntry

Implementation path

  1. Define bounded tagged entries with provenance, parent IDs, content hashes, and visibility.
  2. Append entries to rollout trace; derive indexes rather than introducing a second database.
  3. Require compare-and-append sequence numbers for resolution and supersession.
  4. Project only selected entries into context through the phase-4 fragment machinery.
  5. Expose deterministic queries with hard entry and byte limits.

Exact touch points after baseline

  • codex-rs/core/src/workflow/blackboard.rs — new entry and transition owner.
  • codex-rs/core/src/context/workflow_projection.rs — bounded board projection.
  • codex-rs/rollout-trace/src/model/runtime.rs — append-only persistence and replay.
  • codex-rs/code-mode-protocol/src/description.rs — typed board declarations exposed to code mode.
  • codex-rs/core/tests/suite/workflow_blackboard.rs — integration coverage.

Proof

Trace replay produces byte-identical board state. Concurrent stale resolutions are rejected; provenance survives context projection; query limits prevent a worker from recovering the entire mission ledger through repeated unbounded reads.

Stop: storage and projection only. No subscriptions, worker claiming, autonomous scheduling, semantic search, garbage collection, or cross-run board.
