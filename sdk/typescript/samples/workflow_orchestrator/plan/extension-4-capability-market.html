Select an approach as deliberately as the baseline selects a model. Bounded proposers expose different task shapes before the system funds implementation.

First PR

Collect at most three read-only typed proposals, normalize them against host routing policy, and select one with deterministic rules. The winner runs through the ordinary stage kernel. 

ApproachProposal {
  shape, assumptions, context_needed, capability_requirement,

}

routing.propose(request, { max_proposals: 3 })
routing.selectProposal(proposals, policy_revision) → ProposalDecision

Implementation path

  1. Reserve all proposal invocations before fan-out and use fresh bounded contexts.
  2. Validate every proposal contract; invalid proposals consume their reservation.
  3. Reject proposals that exceed mission authority, deadline, or eligible capability lanes.
  4. Rank capability fit and user value first, then expected execution cost as tie-breaker.
  5. Persist the winner, rejected alternatives, policy revision, and selection reason.

Proof

Fixtures prove a cheaper proposal cannot beat a materially better capability fit, equivalent proposals use cost only as tie-breaker, policy changes invalidate stale decisions, and the selected proposal is carried into implementation without raw proposer transcripts.

Stop: one proposal round and one winner. No negotiation, self-priced tokens, automatic policy learning, reputation scores, or implementation during bidding.
