Extension 5 · Portfolio execution

Turn alternatives into isolated artifacts. Two implementations follow the same mission and are compared by journey evidence before either can become the selected result.

PR contract

Proposed title workflow: compare two isolated implementation candidates

First PR

Run exactly two candidate workflows in host-provisioned isolated workspaces, freeze both diffs, and produce a typed selection. Preserve the winner; discard neither workspace automatically. 

workflow.portfolio.run({
  mission, candidates: [minimal_shape, reusable_shape],
  selection: { journey, integration, complexity }
}) → PortfolioResult {
  candidate_results, evidence, selected_candidate, reason
}

Implementation path

  1. Require two distinct, host-approved workspace roots derived from the same source tree.
  2. Reserve both candidate budgets and capture source-tree identities before inference.
  3. Run candidates independently with identical mission constraints and explicit approaches.
  4. Freeze Git diffs and journey evidence before starting the fresh selector invocation.
  5. Record the selected candidate and rationale; leave application or merge to the host.

Proof

A fixture proves both candidates start from one tree, cannot observe or modify each other, receive the same mission, and remain inspectable after selection. The selector cannot run until both terminal results and frozen evidence exist.

Stop: two candidates, one selector, no synthesis. Do not cherry-pick, merge, rewrite, delete workspaces, or launch portfolio execution for routine mechanical work.
