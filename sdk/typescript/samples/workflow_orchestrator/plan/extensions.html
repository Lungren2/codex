Post-baseline workflow extensions

Five alternative composition models to evaluate only after the eight-phase workflow runtime executes reliably. Each linked document defines one reviewable first PR, not a commitment to its entire architecture.

Shared entry gate

Begin an extension only after workflow invocation, durable StageResult, restricted TypeScript, bounded context, host routing, cancellation, and restart recovery work end to end. A phase-1-through-8 smoke must finish without manual ledger repair.

Directions

Brief Use when First PR proves Do not choose first when
1 · Task capsules Plans must change during execution while every task remains auditable. Mutable decomposition can remain deterministic and sequential. A single coherent workflow already fits the mission.
2 · Recursive workflows A task reveals nested orchestration only after work begins. One child inherits finite authority, cancellation, and budget. Depth and inherited budgets are not yet trustworthy.
3 · Reactive blackboard The next action should emerge from typed unmet needs rather than a fixed sequence. Shared state can aid adaptation without becoming the scheduler. Ownership and termination must remain immediately obvious.
4 · Capability market Approach selection is more uncertain than execution. Bounded proposals improve approach choice enough to justify their cost. The work is mechanical or the proposal cost rivals implementation.
5 · Portfolio execution Two materially different implementations are worth comparing as real artifacts. Journey evidence can select between isolated implementations. The diff is routine or candidate isolation is unavailable.

Recommended experiment order

  1. Task capsules: adds adaptive decomposition without replacing the stage kernel.
  2. Capability market: improves approach selection using the existing router.
  3. Portfolio execution: tests alternatives as artifacts under explicit isolation.
  4. Recursive workflows: adds hierarchy after capsule budgets are measured.
  5. Reactive blackboard: evaluate last because it changes the ownership model most.

Stop: do not combine two extension directions in their first PR. Compare each experiment against the unchanged sequential TypeScript baseline.
