Agent-authored TypeScript workflow runtime

Build one product path in eight product phases and thirteen independently reviewed implementation slices: an agent writes a bounded TypeScript program; Codex compiles and executes it; the program invokes workers under host-owned context, routing, authority, and evidence.

Authority

TypeScript workflow owns control flow
host owns compilation, authority, limits, routing, and facts
worker owns bounded judgment and implementation
StageResult records every attempted transition

Phases

Phase Single outcome Exit gate
1 A JavaScript code cell invokes one workflow-native worker. Typed terminal result and cancellation work end to end.
2A.1 Bounded reservation and terminal events reduce under strict invariants. Pure replay is complete without writer or recovery changes.
2A.2a A synced-fact index proves all stage prerequisites without emitting stages. Malformed ownership never unlocks a source or consumes an attempt.
2A.2b The sole code-cell-bound producer syncs required stage events. Successful calls replay; ambiguous I/O fails closed.
2A.3 Normal rollouts provision traces and root restart owns recovery. Child reload cannot recover live root or sibling stages.
2B Workflow lifecycle terminalizes before cleanup and preserves nested parentage. All live terminal and real restart paths replay with bounded metadata.
2C Code mode enforces every host-owned resource bound. Each exact boundary and a real workflow violation are proven.
3 An agent-authored TypeScript module compiles and runs in the restricted isolate. Source, JavaScript, source map, and compiler evidence are persisted.
4 Workers receive explicit bounded context projections. No unregistered fragment or transcript dump reaches inference.
5 Workflows request capability lanes; the host selects model and effort. Route evidence explains selection, alternatives, and escalation.
6 Intent uncertainty becomes a typed root-owned transition. The user is interrupted only for material ambiguity.
7 Implementation and journey verification prove the requested behavior exists. Behavioral repairs repeat journey verification.
8 Code-quality judgment and optional landing checks follow mission proof. Merge checks run only when landing is requested.

Bootstrap program

Until these primitives are first class, sdk/typescript/samples/workflow_orchestrator/index.ts loops current SDK sessions over these exact phase documents. It is a temporary executor, not the product API. It reserves every attempt before inference, retains the original deadline on resume, and closes abandoned attempts as interrupted. With two repairs allowed per phase, the thirteen-slice worst-case path is explicitly capped at 117 sessions, 45 minutes each, and eight elapsed hours from the first start. Writable sessions run in one isolated worktree under the development Codex home, seeded from an anchored snapshot of the intended source working tree, including untracked files; the shared checkout is never their workspace. The selected HTML contents, complete phase definitions, execution order, and hashes are pinned in the run ledger before the first session.
