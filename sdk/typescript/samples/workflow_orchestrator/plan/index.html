Agent-authored TypeScript workflow runtime

Build one product path in eight narrow increments: an agent writes a bounded TypeScript program; Codex compiles and executes it; the program invokes workers under host-owned context, routing, authority, and evidence.

Authority

TypeScript workflow owns control flow
host owns compilation, authority, limits, routing, and facts
worker owns bounded judgment and implementation
StageResult records every attempted transition

Phases

Phase Single outcome Exit gate
1 A JavaScript code cell invokes one workflow-native worker. Typed terminal result and cancellation work end to end.
2 Every attempted invocation leaves one durable result envelope. Bounds survive failure, cancellation, and process restart.
3 An agent-authored TypeScript module compiles and runs in the restricted isolate. Source, JavaScript, source map, and compiler evidence are persisted.
4 Workers receive explicit bounded context projections. No unregistered fragment or transcript dump reaches inference.
5 Workflows request capability lanes; the host selects model and effort. Route evidence explains selection, alternatives, and escalation.
6 Intent uncertainty becomes a typed root-owned transition. The user is interrupted only for material ambiguity.
7 Implementation and journey verification prove the requested behavior exists. Behavioral repairs repeat journey verification.
8 Code-quality judgment and optional landing checks follow mission proof. Merge checks run only when landing is requested.

Bootstrap program

Until these primitives are first class, sdk/typescript/samples/workflow_orchestrator/index.ts loops current SDK sessions over these exact phase documents. It is a temporary executor, not the product API. It reserves every attempt before inference, retains the original deadline on resume, and closes abandoned attempts as interrupted. With two repairs allowed per phase, the eight-phase worst-case path is explicitly capped at 72 sessions, 45 minutes each, and eight elapsed hours from the first start. Writable sessions run in one isolated worktree under the development Codex home, seeded from an anchored snapshot of the intended source working tree, including untracked files; the shared checkout is never their workspace. The selected HTML contents, complete phase definitions, execution order, and hashes are pinned in the run ledger before the first session.
