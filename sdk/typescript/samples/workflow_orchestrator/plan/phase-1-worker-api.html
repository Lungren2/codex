Phase 1 · Workflow-native worker invocation

Ship one enabling substrate: a JavaScript code cell calls tools.workflow__run(...), core runs one child turn, and the promise resolves to a typed terminal envelope. Phase 3 turns this substrate into the defining TypeScript product.

Contract

workflow__run({
  prompt,
  context: { mode: "fresh" | "all" | "last_n", turns? },
  model?, reasoning_effort?, service_tier?, output_schema?
}) → { worker_id, thread_id, status, output, usage, effective_settings }

Implementation

  1. Add ToolExposure::CodeModeOnly; never expose this as a direct model tool.
  2. Add codex-rs/core/src/workflow/invocation.rs over AgentControl/ThreadManager. Do not re-enter app-server RPC from the active parent turn.
  3. Submit the child turn with Op::UserInput so schema and settings survive.
  4. Return one terminal value; do not reproduce spawn/send/wait lifecycle handles.
  5. Propagate parent cancellation, interrupt the child, and await cleanup.

Exact existing surfaces

  • codex-rs/tools/src/tool_executor.rs:13 — tool exposure.
  • codex-rs/core/src/tools/spec_plan.rs:453 — nested registry construction.
  • codex-rs/core/src/agent/control.rs:88 — worker lifecycle and capacity.
  • codex-rs/core/src/agent/status.rs:6 — terminal message.
  • codex-rs/protocol/src/protocol.rs:552 — full user-turn input.
  • codex-rs/core/src/tools/parallel.rs:158 — cancellation semantics.

Proof

A core integration test runs one schema-constrained fresh worker from a code cell, asserts the parsed terminal result, and proves cancellation leaves no child running. Full and last-N history are separate cases; existing collaboration APIs remain unchanged.

Stop: JavaScript invocation only. No stage policy, TypeScript compilation, routing, retries, review, or DSL.
