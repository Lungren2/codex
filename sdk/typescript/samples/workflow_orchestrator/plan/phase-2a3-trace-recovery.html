Phase 2A.3 · Default provisioning and exclusive recovery

Make the stage trace authoritative in ordinary persisted sessions and make recovery an exclusive root-restart operation, never a child reload side effect.

Implementation

  1. Provision the bundle from the normal persisted rollout directory. Keep CODEX_ROLLOUT_TRACE_ROOT only as an explicit override.
  2. Attach root and child threads to the same in-process writer.
  3. Add private reopen/lease state in writer/reopen.rs. Recovery proceeds only after the prior writer lease is gone; derive root identity from the manifest and rollout startup path rather than trusting a caller-supplied ID.
  4. Terminalize only reservations proven abandoned; preserve identity, attempt, deadline, and parentage. The next attempt remains monotonic.
  5. Tolerate or truncate only a partial final JSONL record; never rewrite earlier durable events. Exercise real close/reopen behavior in dedicated recovery tests.

Exact surfaces

  • codex-rs/rollout-trace/src/thread.rs — default bundle and shared writer.
  • codex-rs/rollout-trace/src/recovery.rs — exclusive root recovery.
  • codex-rs/rollout-trace/src/writer/reopen.rs — private lease and log reconstruction.
  • codex-rs/rollout-trace/src/thread_tests.rs — live child and restart proof.
  • codex-rs/rollout-trace/src/recovery_tests.rs — exclusive reopen and partial-tail proof.

With no override, a persisted rollout gets an adjacent trace. While the original writer is alive, another handle cannot reopen or mutate it. After a real close/reopen, recovery closes only abandoned reservations, preserves immutable fields, and advances the next attempt. An attached child sharing the writer cannot acquire the lease. Target: under 500 complex production lines and under 800 total changed lines.

Stop: actual resumed-child session integration belongs to Phase 2B. No worker cleanup, cancellation policy, code-mode bounds, TypeScript runtime, or app-server API.
