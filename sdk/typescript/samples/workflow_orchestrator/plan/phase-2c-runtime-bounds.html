Phase 2C · Code-mode runtime bounds

Land host-owned isolate limits separately from stage durability. Isolate code may consume authority but cannot widen it.

Single outcome

RuntimeBounds {
  source_bytes, cells, concurrent_cells,
  nested_calls, concurrent_nested_calls,
  stored_bytes, returned_bytes, runtime_ms
}

Implementation

  1. Define one host-owned RuntimeBounds value outside ExecuteRequest. Apply defaults at session construction.
  2. Enforce cumulative source bytes and cell count before admission; enforce concurrent cells with permits released on every terminal path.
  3. Enforce total and concurrent nested tool calls, stored bytes, returned bytes, and expiry of an already-running cell.
  4. Map bound failures into the Phase 2B terminal result without weakening or duplicating the trace lifecycle.

Exact surfaces

  • codex-rs/code-mode-protocol/src/runtime.rs — host-owned bound type and defaults.
  • codex-rs/code-mode/src/session_runtime/mod.rs — admission, permits, deadline, and byte accounting.
  • codex-rs/code-mode/src/session_runtime/tests.rs — table-driven boundary coverage.
  • codex-rs/core/tests/suite/workflow.rs — real workflow bound integration.

Proof

Table-driven tests exercise the exact boundary and first rejected value for every field, including concurrent cells, total and concurrent nested calls, and expiry while a cell is running. A focused workflow integration test proves a bound violation reaches one durable terminal result.
