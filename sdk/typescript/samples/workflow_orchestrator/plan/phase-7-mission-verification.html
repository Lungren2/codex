Phase 7 · Mission-first progress and journey verification

Prove user intent before cleanup. The implementer keeps continuity and uses only targeted progress probes; a fresh tool-capable verifier then follows the real journey. Validation purpose never selects thread granularity automatically.

Modes in this phase

progress_probe Normally inline; confirms behavior is landing without merge-grade proof.
journey_review Fresh when independence helps; follows runtime or entry-to-effect code-path evidence.

Implementation

  1. Add codex-rs/core/src/workflow/validation.rs with validation mode separate from context/granularity mode.
  2. Record implementer decisions, alternatives considered, relevant files, and inline probe evidence without requiring tests.
  3. Give journey verification browser/runtime/tool authority explicitly; a diff alone cannot satisfy the journey contract.
  4. When runtime execution is unavailable, require a bounded trace from user entry point to observable effect and label it weaker evidence.
  5. After any behavioral repair, rerun journey verification before advancing.

Proof
