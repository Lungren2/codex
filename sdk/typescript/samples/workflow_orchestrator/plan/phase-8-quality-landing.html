Phase 8 · Code quality and optional landing gate

Only after the journey works, inspect correctness, integration, maintainability, and code shape. Deterministic repository checks remain a separate, explicit landing request; usability never implies mergeability.

Modes in this phase

code_quality_review Independent structured judgment over final code and mission evidence.
merge_gate Host-run repository commands only when prepare_for_landing is true.

Implementation

  1. Extend review/start with optional model, effort, service tier, output schema, and bounded additional context.
  2. Review the final phase-relative Git diff plus proven mission evidence; do not trust stale implementation summaries.
  3. Classify findings as mission regression or quality issue. Any behavioral repair returns to Phase 7 journey verification.
  4. Resolve landing commands from repository policy, run them in the host command executor, and persist exact output and exit status.
  5. Produce a final narrative: mission interpretation, workers/routes, decisions and rejected alternatives, files and reasons, journey evidence, quality findings, landing evidence, and remaining concerns.
